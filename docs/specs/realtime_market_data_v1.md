# A股实时行情适配器 v1

## 范围

本版本只负责实时行情和分钟K线，不连接券商，不发送、撤销或模拟证券订单。

首个后端复用项目已冻结的 `akshare==1.18.21`：

- 全市场行情使用东方财富快照，失败时可降级到新浪快照；
- 分钟K线优先使用东方财富接口，失败时自动降级到新浪，两者均支持
  1、5、15、30和60分钟；
- 所有证券代码规范化为 `sh600000`、`sz000001` 或 `bj920001`；
- 时间统一为 `Asia/Shanghai`；
- 成交量统一为股，换手率统一为小数；
- 返回值记录供应商时间、接收时间、来源和时间戳质量；
- 显式请求的证券缺失时默认失败，不静默返回不完整结果；
- 健康状态记录最近供应商、成功时间、错误、降级警告、延迟和记录数。

AKShare是HTTP轮询数据源，不属于交易所级推送行情。本适配器适用于研究、影子运行、模拟盘和分钟级执行研究，不对延迟、完整性或商业使用提供保证。

## 使用示例

```python
from abupy.MarketBu import AKShareRealtimeMarketData

feed = AKShareRealtimeMarketData()

quotes = feed.snapshot(["sh600000", "sz000001"])
bars = feed.minute_bars("sh600000", period="1")
health = feed.health().to_dict()
```

持续轮询使用：

```python
feed.poll_snapshots(
    callback=handle_quotes,
    symbols=["sh600000", "sz000001"],
    interval_seconds=5,
)
```

策略必须只使用 `bar_complete=True` 的分钟K线。适配器保守排除与本地当前分钟同时间戳的最后一根K线，避免读取供应商仍在更新的Bar。供应商没有提供行情时间时，`timestamp_quality` 为 `received_at_proxy`，不得把接收时间冒充交易所时间。

新浪分钟线不提供成交额，降级时 `amount` 为空值，但OHLCV、条数、时区、
请求时间范围和数据来源仍会正常标准化。若策略依赖分钟成交额，必须在入口处
显式拒绝该降级结果，不得用零代替缺失值。
新浪接口固定最多返回1,970条；实测1分钟线覆盖约8个交易日，因此它适合盘中
信号和近期缓存补齐，不能作为长期分钟历史库。

## 2026-10-04连通性实测

- 东方财富分钟线：失败，当前环境访问 `push2his.eastmoney.com` 出现代理连接错误；
- 新浪分钟线：成功，`sh600000` 5分钟历史数据单次约0.7至0.8秒；
- Mootdx 0.11.7：自动选线约31秒且返回空数据，三条指定通达信线路分别
  出现调用失败、超时和连接重置，暂不纳入运行时依赖。

## 后续后端

若后续网络环境能稳定连接通达信公共服务器，Mootdx可作为第三层数据源；
当前不应将它加入生产降级链。XtQuant属于需要客户端和账户权限的通道，
不在当前“只需行情适配器”的范围内。任何新后端都应实现同一个
`RealtimeMarketDataAdapter` 接口；推送型实现可以增加订阅生命周期，但不得改变标准化字段含义。
