## 每日内容与时序

1. 收盘后采集当天行情，核对冻结历史和提交链。
2. 使用当天实际开盘行情及既定成交约束，核算此前已经冻结的订单；记录成交、拒单、费用和持仓变化。
3. 使用当天收盘信息更新信号、检查保护性退出，在评审日按原规则审批下一交易日订单并冻结数量。
4. 推送观察名单 Top 10、下一交易日买卖计划及原因、当天实际模拟成交/拒单、当前持仓、现金、净值、累计收益及回撤。

观察候选明确标注“不是买入委托”；计划明确标注“尚未成交”。日报给出计划买入最高价格和初始止损；当前持仓展示的是初始止损参考，不能将其误认成已同步到风控账本的移动止损。移动止损的实际卖出计划和原因由冻结策略决定。

这是**日线研究模拟盘**：下一交易日开盘的撮合结果在该日日终核算和推送，不能称为盘中实时成交。没有券商连接或真实证券订单。继续沿用前瞻实验注册时固定模型，与历史回测的滚动模型更新方式存在差别，不能拼接两类收益。

## 幂等、告警与边界

- 原策略的同日提交幂等；通知采用账户、日期、消息分片的稳定 ID，同时检查待发队列与已发送回执。正常重跑不重复入队。
- 入队与发送成功分开记录；调度检查 `sent-<id>.json`，没有回执就告警，不声称已送达。机器人若在发送成功但本地回执落盘前崩溃，外部传输仍可能重复，不能承诺跨系统严格 exactly-once。
- 行情缺失时，使用交易日历区分正常休市和交易日数据陈旧。日历覆盖不足或接口失败也不能猜测为休市。
- 旧日期不能标为今日信号。源码/依赖漂移、漏采交易日、历史修订、未支持的公司行动、到达预登记评估节点等，均保留最后有效账本并通知，不自动修改策略或回填。
- 企业微信日志与收件人信息保存在用户私有运行目录；密钥没有复制到策略冻结代码或仓库。
- 每日“今日策略”查询文件会更新为最新 Alpha158 报告。既有 VCP 账户、调度及成交推送暂保留原设置，等待用户对旧提醒的偏好回复。
- 用户本次授权的是研究模拟运行和通知，不是策略已通过统计准入。原始注册中的 `paper_admitted=false`、`live_admitted=false` 和核心不发送消息的契约不被篡改；通知在独立侧边服务中执行，授权记录于 `activation.json`。

## 运维命令

在项目目录使用以下命令，均会校验并进入已部署的通知服务副本：

```sh
.venv/bin/python -B scripts/run_alpha158_daily_service.py status
.venv/bin/python -B scripts/run_alpha158_daily_service.py preview
.venv/bin/python -B scripts/run_alpha158_daily_service.py run
```

`preview` 不推进交易、不发送通知；`run` 推进当天研究账户并发布日报。不要再次初始化原始前瞻账户，不要手工复制旧行情冒充新交易日。暂停或调整调度应通过 Codex 的定时任务管理工具更新 ID `alpha158`；不要直接编辑自动化配置文件。
