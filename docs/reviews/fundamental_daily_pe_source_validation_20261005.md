# 每日 PE 与 PIT 基本面数据源验证（2026-10-05）

## 结论

当前基本面研究受阻，并不是因为无法获得每日 PE。BaoStock 对冻结的 50 只分层样本均返回了历史日频估值数据，交易日正 PE 加权覆盖率为 81.46%，还覆盖了退市样本。但这些数据没有公开、可审计的历史修订版本链，无法证明今天下载到的历史 PE 与当时真实可见的数据完全一致。因此它只能用于覆盖率检查和交叉核验，不能解除项目的 PIT（point-in-time）门禁，也不能直接进入正式回测。

真正的阻塞项是：需要知道每个交易日估值分母所使用的 TTM 净利润版本、该版本首次可用日期、后续修订日期和修订前数值。每日 PE 本身只是供应商计算后的结果；如果供应商用后来修订的利润回填历史 PE，回测就会产生未来函数。

## 候选数据源判断

### BaoStock

官方数据计划列出日频 `peTTM`、`pbMRQ`、`psTTM`、`pcfNcfTTM` 字段，也提供历史财务指标，但没有说明估值字段的历史版本、追溯更正规则或修订前值保存方式：<https://github.com/zxygithub/baostock/blob/master/docs/data_download_plan.md>。

判断：适合免费覆盖率检查、异常点定位和供应商之间的横向比对；不适合作为当前项目的主 PIT 基本面源。

### Tushare Pro

官方 `daily_basic` 文档提供 `pe_ttm`、总市值、总股本和流通股本：<https://tushare.pro/document/2?doc_id=32>。利润表接口提供公告日、实际公告日和更新标识，并定义了保留调整前数据的报表类型：<https://tushare.pro/document/2?doc_id=33>。

判断：具备构建 PIT 财务版本链所需的关键字段，值得做凭证化样本验证；但本机没有 Tushare token，也尚未验证订阅权限、历史深度、退市证券和修订前记录完整性。当前状态只能记为“能力看起来可行，尚未通过样本验证”。

### BigQuant

官方 PIT 利润表说明数据从 2005 年开始，包含 `date`、`report_date` 和 `change_type`，区分首次披露和后续变更：<https://bigquant.com/data/datasources/cn_stock_financial_income_general_pit>。API 文档把 `fs_publish_date` 定义为财务数据实际可用日期，并说明 A 股覆盖包含退市证券：<https://bigquant.com/wiki/doc/UJyXClKw0p>。其财务数据目录也明确说明同一报告期可因不同公告日存在多条记录：<https://bigquant.com/data/categories/-%E8%B4%A2%E5%8A%A1%E6%95%B0%E6%8D%AE>。

判断：公开文档中的 PIT 语义最明确，是下一轮优先试用对象；但仍需验证账户权限、费用、导出限制、字段完整性和真实样本，不能仅凭文档进入回测。

### 现有东方财富与巨潮结构化数据

现有采集能够支持公告日匹配、当前截面和部分历史财报检查，但历史修订版本与股本口径仍不完整。它们可以继续作为官方公告证据和异常复核源，暂时不能单独承担 PIT 主数据源。

## 下一轮准入验证

下一轮只验证一个候选供应商，沿用同一 50 只冻结样本，不因结果调整证券或阈值。优先顺序为 BigQuant PIT，其次是 Tushare 财务版本数据。正式回测前必须同时满足：

1. 2005 年至当前区间包含在市与退市证券，能区分亏损导致的无 PE、字段缺失和停牌。
2. 每条利润记录具有首次可用日期；已修订财报能保留修订前值和后续版本，而不是只返回最新值。
3. 对已知更正案例，按任一历史交易日查询时只能看到当时已经发布的版本。
4. 使用当时可见的 TTM 净利润和当日总市值重建 E/P，能够与供应商当日估值在事先规定的容差内一致。
5. 股本与市值口径可核对，除权、送转、回购、增发和退市区间不会静默改变历史分母。
6. 原始响应、查询参数、时间戳和哈希全部归档；重复下载若发生历史变化，必须能解释为带版本的供应商更正。

在这些条件通过前，不运行基本面收益回测，也不把基本面信号加入模拟盘。当前 Alpha158 价格策略和 `event_exit_only` 前瞻账户保持不变。
